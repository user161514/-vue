# 2026-10-04 工作日志

## 诊断:部门删除失败(根因定位,未改用户代码)

**根因:`deletedept` 传的是裸值 body,axios 不会自动加 `Content-Type: application/json`,
导致 Spring 收不到请求体,id 根本没到后端。**

### 三组对照实验(一锤定音)

同一个接口 `DELETE /api/delete`,后端方法是
`com.itheima.Controller.Emp22Controller.emp22List10086(java.lang.Integer)`:

| 实验 | 请求 | 后端返回 |
|---|---|---|
| ① 浏览器 XHR(前端现状) | `DELETE api/delete`, body=`1`, **无 Content-Type** | `code:500 Required request body is missing` |
| ② curl 手动加 json 头 | body=`9999` + `Content-Type: application/json` | `code:200 success` |
| ③ curl 加 json 头但 body 换对象 | body=`{"id":9999}` + json 头 | `code:500 JSON parse error: Cannot deserialize Integer from Object value` |

**结论**:后端要的是 `@RequestBody Integer id` ——必须是**裸值** body + **必须带 json 头**。

**axios 的坑**:只有 `data` 是**对象**时才会自动加 `Content-Type: application/json`;
传裸数字/字符串时 axios 不知道该加什么,干脆不加 → 请求体在 Spring 眼里是空的。

### 修复方案(已告知用户,未动手)
```js
// src/api/dept.js
export const deletedept = (id) =>
  request.delete(`/delete`, {
    data: id,
    headers: { "Content-Type": "application/json" },
  });
```
```js
// src/view/dept/index.vue —— 第二个坑
if (res.code === 200) { /* 成功 */ } else { /* 失败 */ }
```

### 第二个坑:会误报"删除成功"
后端出错时 **HTTP 状态码仍是 200**(Result 封装),body 里 `code: 500`。
所以 `if (res.code)` 里 `500` 是非 0 → 判真 → 弹"删除部门成功" → 刷新后数据没少。
表现就是"提示成功了但没删掉"。

### 踩坑记录(方法论,下次直接用)
- **光 curl 测通不算数**。必须用 `agent-browser` 打开 `localhost:5173` 在真实浏览器里复现,
  才能抓到"浏览器发出的请求"与"curl 发的请求"的差别(本例就是 Content-Type 头)。
- 用 `agent-browser eval` 钩 `XMLHttpRequest.prototype.open/send` 可以抓到实际发出的
  method/URL/body;在 `send` 里直接 `return` 就能**阻断请求而不影响后端数据**。
- 钩子注入后要记得恢复:`XMLHttpRequest.prototype.open = oOpen; ... = oSend;`
- `agent-browser eval` 里不能用顶层 `return`,要包一层 `(function(){...})()`;
  eval 是独立上下文,`var` 声明的变量(oOpen/oSend)仍在全局可取回。
- 探测后端接口时用 `curl --noproxy "*"`,并且**要对比"带/不带 Content-Type"**,别只测一种。
